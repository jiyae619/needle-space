How Needle Space finds a cafe you can work from

Needle Space is a two-tier system. A daily offline pipeline uses LLMs to read reviews, Reddit threads and photos, and turns them into structured work tags with quotes as evidence. The online search path never calls an LLM. It embeds the query once and ranks cafes in Postgres. In short, this is retrieval without generation, and that choice is what keeps the cost of a search near zero.

The system as it runs in production today

What happens when someone types “quiet spot in Bellevue for deep work”

  1. The search bar waits 800 ms after the last keystroke and ignores fragments under four characters, because every search spends one embedding on a free tier of 3 requests a minute.
  2. The place parser removes “in Bellevue” and turns it into a hard SQL filter on the postal address. Embeddings are good at vibe and bad at geography.
  3. Only “quiet spot for deep work” is sent to Voyage-3, which returns a 1024-number vector. Repeat queries come from an in-memory cache.
  4. match_cafes() ranks cafes by cosine similarity inside the place filter and any chip filters, and returns 100 candidates.
  5. The route removes closed cafes and applies the open-now and productivity chips, then returns the top 30. If Voyage fails, the same filters rank by productivity score and the page says semantic search is limited.

Inside the offline tier

The LangGraph tagging graph

Each cafe runs through this state machine once. The graph's job is reliability. It retries bad model output, stops before it can do damage, and writes each cafe in a single update so no row is ever half-tagged.

Verified

What was broken, and what changed

I built a local copy of the stack to test these: Postgres 16 with pgvector and all 11 migrations, PostgREST (the API layer Supabase uses), and the production Next.js build. A deterministic stand-in replaced Voyage and Gemini, since no API keys were available. I ran every check on the original code and on the fixed code. The dataset had 72 synthetic cafes in the real shape.

Open gaps

What is still missing, in priority order

These need a decision, a secret, or data I could not reach from here. G1 to G6 are marked on the first diagram.

  • G1High

    The Google server key is still stored in the public cafes table.Code fixed · rotate the key fetch-cafes.mjs saves a photo URL with the key appended. Anyone with the public Supabase key can read the table directly.

    Rotate the key and restrict it to the Places API. Store photo URLs without the key, and add cache-photos.mjs to the daily workflow.

  • G2High

    The quality gate rarely gates.Built It passes any run that touches fewer than 25 cafes, which is almost every daily run. It skips cafes that only vision changed. And it measures coverage (fewer “unknown”), not accuracy, so confident wrong tags pass.

    Gate on a rolling window since the last passing run, and add accuracy against human labels once they exist.

  • G7High

    No human-labeled ground truth.Tool built · labels needed The tagging eval compares the LLM to the regex tagger, which the code itself shows is unreliable: it called 301 of 464 cafes quiet and never called one loud. The retrieval golden set was drafted from the system's own tags, and some labels contradict the location filter.

    Label 80–100 cafes by ID in the existing /admin tool. Report accuracy per attribute and nDCG@10 for search.

  • G3Medium

    One visitor can use up search for everyone.Built There is no rate limit on /api/search, and Voyage's free tier allows 3 embeddings a minute across all users.

    Add a per-IP limit and move to Voyage's paid tier, which costs cents a month at this volume.

  • G4Medium

    Every search returns 30 cafes, however weak the match.Built · set the floor from logs There is no similarity floor, so “pizza” still fills a page.

    Log similarity scores, pick a floor from real queries, and show “no close match” below it.

  • G5Medium

    Stored scores and vectors are stale until one re-run.Your action The code is fixed, but the database still holds the inflated values.

    Run node scripts/finalize-cafes.mjs --all once (about $0.02 of Voyage usage, now about 7 minutes with batching).

  • G6Medium

    Every cafe is embedded twice.Built The tagger embeds, then finalize embeds again and overwrites it. With free-tier pacing, a --force run takes longer than the job's 180-minute timeout.

    Now embedded only in finalize, 25 cafes per request.

  • G8Medium

    The pipeline can stall or skip stages.Mostly built One persistent refresh error fails the job every day and blocks every later stage. Vision tags the first Google photo, which is often a logo, and marks the cafe as done. Research re-stamps its date every 30 days, which triggers re-tagging even when nothing changed.

    Later stages now run when refresh fails, and vision waits for a cached photo. Change-aware research is still planned.

  • G9Medium

    The search index loses most of what it knows.Planned Each vector is built from tags written as key=value plus 800 characters of reviews. Google's review summary is fetched and then thrown away.

    Save the summary and embed plain sentences (“Fast WiFi. Outlets at most tables.”).

  • G10Low

    Housekeeping.

    • The search log is publicly readable. Fixed
    • @anthropic-ai/sdk and @langchain/anthropic are installed but unused.
    • CI never runs a build.
    • The docs disagree with the code: CLAUDE.md says Vercel but the repo deploys to Netlify, and the README cites 252 cafes and figures that contradict EVAL.md.

For the portfolio case study

What these diagrams support, and what they don't yet

Claims you can make now

  • The LLM runs offline only. Search costs one cached embedding and no generation.
  • Location is handled as a fact, not a vibe. The place parser fixed real misses, such as a Seattle cafe ranking for a “Bellevue” search.
  • The graph is built for reliability: validated output, retries that tell the model what went wrong, atomic writes, and evidence quotes checked against their sources.
  • The team distrusts its own signals where evidence says to. The keyword noise tag was dropped because it said “quiet” to vibe words.

Hold these until there are human labels

  • Any accuracy figure. Current numbers measure agreement with a regex, and coverage.
  • Most of the 90.9% WiFi “agreement” is both taggers saying “unknown” (226 of 252 cafes).
  • “Search accuracy lift.” The retrieval eval measures a hit in the top 10 against labels partly drafted from the system's own tags.
