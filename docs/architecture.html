How Needle Space finds a cafe you can work from

Needle Space is a two-tier system. A daily offline pipeline uses LLMs to read reviews, Reddit threads and photos, and turns them into structured work tags with quotes as evidence. The online search path never calls an LLM. It embeds the query once and ranks cafes in Postgres. Since the review, every fix and the next phase have shipped to the live site, and a third input has joined the two: a person visiting the cafe.

The same system, with the gaps closed and a person in the loop

The layout matches the diagram above, so you can compare them box by box. Nothing moves the LLM into the search path. The new lane at the bottom is Visit mode: what a person sees in the cafe goes straight into the same table the pipeline writes, and wins over the model.

What happens when someone types “quiet spot in Bellevue for deep work”

  1. The search bar waits 800 ms after the last keystroke and ignores fragments under four characters. The server then allows each visitor 8 embeddings a minute, so one person can't use up the free tier's shared budget of 3 a minute.
  2. The place parser removes “in Bellevue” and turns it into a hard SQL filter on the postal address. Embeddings are good at vibe and bad at geography.
  3. Only “quiet spot for deep work” is sent to Voyage-3, which returns a 1024-number vector. Repeat queries come from an in-memory cache.
  4. match_cafes() ranks cafes by cosine similarity inside the place filter and any chip filters, using a person's label first where one exists. It returns 100 candidates.
  5. The route drops closed and hidden cafes, applies the open-now and productivity chips, and returns the top 30. The query and its best similarity go to a private log, which will set the “no close match” floor.

Human in the loop

Visit mode: updating a cafe from inside it

The AI tags are only as good as what reviewers happened to mention. Twelve cafes had no score at all, because no review said anything about WiFi, outlets or noise. Several are not work spots at all, such as convenience stores and a grocery store. Visit mode lets the person who is actually there record what they see, from a phone, in under a minute.

  1. Find the cafe. Nearest cafes by the phone's location, or search by name. A “Needs a visit” list puts unscored cafes first.
  2. Tap what you see. One tap each for WiFi, outlets, noise, laptops and seating. The site's current tag is a hint, not a preset, so every tap is a real observation.
  3. Add a note and a photo. The phone shrinks the photo to 1600 px and removes its location data before upload. A photo can become the cafe's main image.
  4. Mark it visited, or hide it. “I was here” verifies the cafe. “Not a work spot” removes it from lists, search and the MCP server, and can be undone.

Tags and notes show on the site the moment they are saved. The productivity score and search vector catch up on the next daily pipeline run. Each label also becomes part of the answer key: once 20 cafes are labeled, the quality gate starts failing runs whose tag accuracy drops.

Inside the offline tier

The LangGraph tagging graph

Each cafe runs through this state machine once. The graph's job is reliability. It retries bad model output, stops before it can do damage, and writes each cafe in a single update so no row is ever half-tagged.

Verified before shipping

Before any of this reached production, I tested it on a local copy of the stack. That copy ran Postgres 16 with pgvector and all migrations, PostgREST (the API layer Supabase uses), and the production Next.js build. A deterministic stand-in replaced Voyage and Gemini. What these diagrams support, and what they don't yet

Claims you can make now

  • The LLM runs offline only. Search costs one cached embedding and no generation.
  • Location is handled as a fact, not a vibe. The place parser fixed real misses, such as a Seattle cafe ranking for a “Bellevue” search.
  • The graph is built for reliability: validated output, retries that tell the model what went wrong, atomic writes, and evidence quotes checked against their sources.
  • People outrank the model. An in-person tool on a phone feeds labels that override AI tags and double as the answer key for evaluation.
  • Silent failures were found and closed. A rate limiter that failed open, a log that never wrote and dropped embeddings reported as success now either work or turn the run red.

Hold these until there are 20+ human labels

  • Any accuracy figure. Current numbers measure agreement with a keyword tagger, and coverage.
  • Most of the 90.9% WiFi “agreement” is both taggers saying “unknown” (226 of 252 cafes).
  • “Search accuracy lift.” The retrieval eval measures a hit in the top 10 against labels partly drafted from the system's own tags.
